# Design Doc: /finding-resources Skill

**Status:** Draft
**Author:** Codex
**Created:** 2026-05-21
**Last Updated:** 2026-05-21

---

## 1. Overview

The `finding-resources` skill adds a version 4 Vidbyte learning utility for comprehensive resource discovery. When invoked with `/find-resource <topic>` or `/finding-resources <topic>`, it performs a source-type-aware web research pass across textbooks, academic papers, white papers, practitioner writing, case studies, university course materials, official documentation and standards, and conference talks, then returns a curated map organized by resource type, depth level, and role in the learning path.

---

## 2. Goals & Non-Goals

### Goals

- Create a new prompt skill package under `skills/finding-resources/`.
- Support `/find-resource <topic>` as the primary invocation and `/finding-resources <topic>` as an alias.
- Require live web search for every non-empty invocation because resource availability, editions, URLs, and current authoritative sources change over time.
- Search each major source type independently instead of relying on generic search results.
- Prefer domain-authoritative locations: university pages, academic databases, publisher catalogs, official docs, standards bodies, known technical blogs, institutional labs, and credible organization case studies.
- Return results organized by source type with depth level, orientation, subdomain, reason to read, and source link.
- Flag foundational versus applied/case-study resources.
- Surface latest editions or most recent canonical versions where possible.
- Exclude content farms, listicles, shallow explainer pages, SEO aggregators, and low-signal reposts.
- Register the skill under the `learning` category and version `4`.
- Provide local helper scripts and references that encode the source-type search plan, scoring rubric, and domain source mapping without adding package dependencies.

### Non-Goals

- Creating a new Python CLI command, backend endpoint, or Vidbyte storage artifact.
- Guaranteeing exhaustive coverage of every possible source on the public internet.
- Downloading or redistributing copyrighted textbooks, papers, videos, or paywalled material.
- Bypassing paywalls or access controls.
- Producing a full literature review or answering the topic itself; this skill maps what to read.
- Replacing `/research`, `/find-papers`, or `/docs-tldr`; this skill spans resource formats and routes users toward those deeper tools when needed.
- Adding new npm dependencies or browser automation requirements.

## 3. Background & Context

The repo stores installable skills as `skills/<name>/SKILL.md`, with optional `scripts/`, `references/`, and `assets/` directories copied by the installer. Validation requires lowercase hyphen-case names, matching directory/frontmatter names, non-empty descriptions, and manifest/version entries that reference existing skill directories.

Existing research-adjacent skills solve narrower problems. `/research` synthesizes evidence for a question from peer-reviewed sources. The planned `/find-papers` skill focuses on academic papers. `/docs-tldr` focuses on official docs for a library. None gives a broad learning-resource landscape across canonical books, university courses, industry case studies, lab white papers, practitioner essays, standards, and talks.

This skill belongs in version 4 alongside other learning utility skills. It is prompt-led because the host harness owns web search and browsing. Helper scripts are included only for deterministic argument parsing, search-plan generation, and offline ranking of candidate metadata supplied by the agent or harness.

## 4. Requirements

### Functional Requirements

1. The repo SHALL contain `skills/finding-resources/SKILL.md` with frontmatter `name: finding-resources`.
2. The skill SHALL activate on `/find-resource <topic>` and `/finding-resources <topic>`.
3. Empty invocations SHALL show concise usage and examples.
4. The skill SHALL perform live web search for every non-empty invocation.
5. The skill SHALL classify the topic's likely domain and subdomains before searching.
6. The skill SHALL build separate search queries for these source types: textbooks and publisher catalogs, research papers and preprints, white papers, practitioner blog posts, case studies, university course pages and lecture notes, official documentation and standards, and conference proceedings or talks.
7. The skill SHALL prefer authoritative source locations for the inferred domain.
8. The skill SHALL avoid content farms, SEO listicles, shallow explainers, autogenerated summaries, scraper mirrors, and generic "best resources" pages unless used only as leads to primary sources.
9. The skill SHALL deduplicate resources by normalized URL, DOI/ISBN where present, title, and author/organization.
10. The skill SHALL label every retained resource with a depth level: `introductory`, `intermediate`, or `advanced`.
11. The skill SHALL label every retained resource with an orientation: `foundational`, `applied`, `case-study`, `reference`, or `current-frontier`.
12. The skill SHALL note the field or subdomain for each resource when the topic spans multiple areas.
13. The skill SHALL surface the latest edition or official current version for foundational textbooks, standards, or documentation when discoverable.
14. The skill SHALL include a one-sentence reason each resource is worth reading.
15. The skill SHALL include direct links and cite source pages used for each resource.
16. The skill SHALL return resources grouped by source type, plus a short recommended reading order.
17. The skill SHALL explicitly state when a source type was searched but no high-quality result was found.
18. The skill SHALL honor optional flags:
    - `--level intro|intermediate|advanced|all`
    - `--domain <domain>`
    - `--recent`
    - `--foundational`
    - `--applied`
    - `--limit <N>`
19. The skill SHALL keep search bounded by default: 2-4 queries per source type and 3-5 retained resources per source type.
20. The skill SHALL never fabricate citations, editions, DOI values, ISBN values, authors, venues, dates, or links.

### Non-Functional Requirements

- **Performance:** Default invocation should target a 2-4 minute research pass, bounded by query and result limits. The skill may ask the user to approve a deeper pass for very broad domains.
- **Scalability:** Each invocation is stateless. Reference maps can grow without changing installer architecture.
- **Security:** The skill must not request credentials, bypass paywalls, execute arbitrary remote code, or construct Vidbyte backend requests.
- **Observability:** The skill should briefly report the search plan before or during execution so the user can see which source types are being covered.
- **Reliability / error tolerance:** Source-specific failures should degrade gracefully; failed searches are noted rather than silently omitted.

## 5. High-Level Design

The change adds a self-contained prompt skill with optional helper files. The installer already discovers and copies skill directories, so no installer routing changes are needed. Registry changes are limited to `skills-manifest.json` and `lib/skill-versions.json`.

Runtime flow:

```text
/find-resource <topic>
  |
  v
[Parse invocation and flags]
  |
  v
[Infer domain/subdomains]
  |
  v
[Build source-type search plan]
  |
  v
[Run live web searches by source type]
  |
  v
[Score, deduplicate, classify depth/orientation]
  |
  v
[Return curated map + reading order + gaps]
```

Key decisions:

- **Canonical package name:** Use `finding-resources` for the skill directory and frontmatter because that matches the requested skill name. Support `/find-resource` as the primary slash command because the user's outline names that command.
- **Prompt-led web research:** Do not add a web-search API integration. Host harnesses differ in their search tools, and this repo currently packages skills rather than runtime network clients.
- **Scripts as local heuristics:** Include scripts for parsing args, producing query templates, and ranking candidate metadata. They are useful when a harness can run local scripts, but `SKILL.md` remains the source of truth.
- **Learning category:** Register under `learning`, consistent with existing utility learning skills such as `question`, `research`, `practice`, and the v4 design docs.

## 6. Detailed Design

### 6.1 Skill Definition

**File(s):** `skills/finding-resources/SKILL.md`
**Type:** New file

#### What it does

Defines the activation rules, argument parsing, search workflow, source-quality rubric, output format, and prohibitions for the `/find-resource` and `/finding-resources` commands.

#### Interface / API

```markdown
---
name: finding-resources
description: >
  Use when the user invokes /find-resource or /finding-resources to find a
  comprehensive, high-quality learning-resource map for a topic across books,
  papers, white papers, practitioner writing, case studies, courses,
  documentation, standards, and talks.
---
```

Supported invocation forms:

```text
/find-resource <topic>
/finding-resources <topic>
/find-resource <topic> --level advanced
/find-resource <topic> --domain distributed-systems
/find-resource <topic> --recent
/find-resource <topic> --foundational
/find-resource <topic> --applied
/find-resource <topic> --limit 20
```

Output shape:

```markdown
## Resource Map: <topic>

## Search Coverage

## Textbooks and Academic Books
- [Title](url) - depth: advanced; orientation: foundational; subdomain: ...
  Why it matters: ...

## Research Papers and Preprints
...

## Recommended Reading Order
1. ...

## Gaps and Caveats
...
```

#### Logic / Algorithm

1. Detect `/find-resource` or `/finding-resources` at the start of the user prompt.
2. If no topic is present, print usage and stop.
3. Parse flags and normalize the requested topic.
4. Infer likely domain and subdomains, using `--domain` when supplied.
5. Load or follow the source-type playbook.
6. Generate targeted queries for each source type.
7. Run live web search by source type.
8. Open or inspect promising primary sources when needed to verify title, author/organization, date, edition/version, and credibility.
9. Score resources using authority, relevance, depth fit, freshness, and originality.
10. Deduplicate candidates.
11. Group retained resources by source type.
12. Classify depth and orientation.
13. Build a reading order from foundational/introduction through applied/current-frontier material.
14. Return the final resource map with links and caveats.

#### Edge Cases & Error Handling

- Empty command prints usage.
- Overly broad topics trigger either a scoped assumption or a concise clarification request if the domain is genuinely ambiguous.
- Search unavailable produces a clear message that live web search is required.
- Paywalled resources can be listed if bibliographic details are public, but the skill must not imply full access.
- Conflicting editions are resolved toward the current official edition, with older canonical editions noted only when still widely cited.
- No high-quality result for a source type is reported under `Gaps and Caveats`.

### 6.2 Argument Parser Helper

**File(s):** `skills/finding-resources/scripts/parse-finding-resources-args.js`
**Type:** New file

#### What it does

Parses a slash-command argument string into a topic and options object for harnesses that can run local scripts or for manual verification.

#### Interface / API

```javascript
export function parseFindingResourcesArgs(input) {
  return {
    topic: "string",
    command: "find-resource" | "finding-resources",
    level: "intro" | "intermediate" | "advanced" | "all",
    domain: "string | null",
    recent: false,
    foundational: false,
    applied: false,
    limit: 40
  };
}
```

Optional CLI usage:

```bash
node skills/finding-resources/scripts/parse-finding-resources-args.js "/find-resource causal inference --level advanced --recent"
```

#### Logic / Algorithm

1. Strip command prefix.
2. Tokenize quoted and unquoted arguments.
3. Extract supported flags.
4. Validate enumerated values for `--level`.
5. Clamp `--limit` to a reasonable range, for example 5-80.
6. Return normalized topic and defaults.

#### Edge Cases & Error Handling

- Missing topic returns an error field instead of throwing.
- Unknown flags are collected in `unknownFlags` for user-facing feedback.
- Non-numeric `--limit` returns a validation error.

### 6.3 Search Plan Helper

**File(s):** `skills/finding-resources/scripts/build-search-plan.js`
**Type:** New file

#### What it does

Builds source-type-specific search query templates from a normalized topic, optional domain, and flags. It does not perform network search.

#### Interface / API

```javascript
export function buildSearchPlan({ topic, domain = null, recent = false, foundational = false, applied = false }) {
  return [
    {
      sourceType: "textbooks",
      queries: ["..."],
      authorityTargets: ["..."],
      rejectPatterns: ["..."]
    }
  ];
}
```

#### Logic / Algorithm

1. Create base topic phrases and domain-qualified variants.
2. Emit 2-4 query templates per source type.
3. Add source-specific operators and phrases such as `site:edu syllabus`, `textbook`, `lecture notes`, `white paper`, `case study`, `standard`, `conference talk`, `proceedings`, and source names from the domain map.
4. Add recency terms when `--recent` is set.
5. Add foundational or applied terms when those flags are set.

#### Edge Cases & Error Handling

- Broad fields receive queries for subdomain discovery as well as direct resource lookup.
- Domain unknown falls back to general high-authority targets.
- Query strings are bounded and human-readable.

### 6.4 Resource Ranking Helper

**File(s):** `skills/finding-resources/scripts/rank-resources.js`
**Type:** New file

#### What it does

Scores already-collected candidate metadata. The agent or harness supplies candidate objects gathered through web search; the script ranks and groups them deterministically.

#### Interface / API

```javascript
export function rankResources(candidates, options = {}) {
  return {
    accepted: [],
    rejected: [],
    duplicates: []
  };
}
```

Candidate shape:

```json
{
  "title": "string",
  "url": "string",
  "sourceType": "textbooks",
  "publisherOrHost": "string",
  "authors": ["string"],
  "year": 2026,
  "snippet": "string",
  "doi": "string | null",
  "isbn": "string | null"
}
```

#### Logic / Algorithm

1. Reject obvious low-quality hosts and content-farm patterns.
2. Normalize URLs and titles.
3. Deduplicate by DOI, ISBN, canonical URL, and normalized title.
4. Score authority, relevance, originality, recency, and source-type fit.
5. Return accepted candidates grouped and sorted by score.

#### Edge Cases & Error Handling

- Missing optional metadata lowers confidence but does not automatically reject a resource.
- Official docs, standards, and canonical older books are not penalized solely for age.
- Recent but shallow content is rejected if it fails authority or originality checks.

8. Given a topic spanning multiple subdomains, each resource lists the relevant subdomain.
9. Given a textbook result with multiple editions, the current edition is preferred and the edition/version is noted where available.
10. Every final resource entry includes a link, depth label, orientation label, and reason to read.

## 14. Alternatives Considered

### Alternative 1: Name the skill `find-resource`

- What: Use `skills/find-resource/SKILL.md` and frontmatter `name: find-resource`.
- Why rejected: The user requested the `/finding-resources` skill for version 4. Using `finding-resources` as the package name preserves that request while still supporting the outlined `/find-resource` command as the primary invocation.

### Alternative 2: Pure `SKILL.md` without helper files

- What: Put all search planning and scoring instructions in the prompt file only.
- Why rejected: The source-type query matrix and ranking rubric are complex enough to benefit from reusable local helpers and references. The repo already supports optional `scripts/` and `references/` directories.

### Alternative 3: Full API-backed research CLI

- What: Add a Python CLI command and Vidbyte backend endpoint for saving resource maps.
- Why rejected: The requested behavior is live discovery and inline curation. Backend persistence would require dataclasses, routing, endpoint support, smoke tests, and server-side changes that are outside the core resource-finding value.

### Alternative 4: Only search academic databases

- What: Implement this as a broader version of `/find-papers`.
- Why rejected: The central premise is that high-quality learning material lives across different source types. Only searching academic databases would miss textbooks, course notes, official docs, standards, practitioner posts, white papers, and case studies.

### Alternative 5: Use generic web search and organize whatever appears

- What: Run a broad query like "best resources for <topic>" and categorize the top results.
- Why rejected: This is exactly the failure mode the skill is meant to avoid. The skill must target each source type directly and exclude generic resource listicles unless they lead to primary sources.
