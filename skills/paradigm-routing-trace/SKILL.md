# Paradigm Routing Reasoning Trace

## Goal
Use Paradigm Routing to answer the user's question through explicit paradigm selection and within-paradigm execution, building a reasoning trace that records both the routing decision and the reasoning it enables. The trace should evaluate the problem against all six paradigms — Direct, Chain-of-Thought, ReAct, Plan-Execute, Reflection, ReCode — select the best-fit paradigm with justification, then produce numbered reasoning items structured by that paradigm's interaction pattern. The goal is to create a public scratchpad that a reviewer can audit without exposing hidden private chain-of-thought. Center the scratchpad on paradigm assessment, subquestions, assumptions, evidence, contrasts, tests, intermediate conclusions, and implications, because those artifacts make paradigm routing useful rather than decorative. Preserve the user's domain, constraints, definitions, and evidence standards so the trace stays tied to the actual task. Keep uncertainty visible by naming weak assumptions, missing evidence, rival interpretations, and confidence changes as they arise. Write the result to root memory/{question_name}.md so the reasoning trace becomes a durable project artifact.

## Instructions
Derive {question_name} from the user's actual question by lowercasing it, replacing non-alphanumeric runs with hyphens, trimming extra hyphens, and using reasoning-trace if no safe name remains. Create the root memory directory when needed, then write or replace memory/{question_name}.md with this trace. Start the file with the question, selected strategy, scale note, source constraints, and paradigm routing assessment. Build the scratchpad by repeatedly applying the paradigm routing move: evaluate the problem's characteristics against each paradigm's decision criteria, select the best-fit paradigm, then reason through the problem using that paradigm's interaction pattern. Use a medium-depth trace by default, usually around 100 numbered lines, unless the user asks for a different depth. Prefer concise public reasoning artifacts over hidden deliberation, and make every numbered item contribute a question, observation, test, comparison, inference, or synthesis. End the file with a synthesis and final answer that follow from the trace, including any important uncertainty that remains.

## Background Information About The Reasoning Strategy
Paradigm Routing is a meta-reasoning strategy that operationalizes the Select-then-Solve framework from Zhou et al (2026). Before producing any reasoning, the strategy evaluates the problem against six candidate inference-time paradigms and routes to the one best suited to the problem's characteristics. The six paradigms are: Direct (single-pass generation, no intermediate reasoning — best for factual retrieval and simple transformations), Chain-of-Thought (stepwise natural language reasoning — best for multi-step logical and mathematical problems where intermediate steps improve correctness), ReAct (interleaved reasoning and tool-use or action — best for problems requiring external information, environment interaction, or interleaved reasoning-action cycles), Plan-Execute (explicit planning phase followed by execution — best for complex multi-phase problems that benefit from decomposition before execution), Reflection (generate, self-critique, and regenerate — best for problems with verifiable solutions where self-critique improves quality), and ReCode (sandboxed code-based reasoning with execution feedback — best for computational, symbolic, or code-execution problems).

The empirical foundation comes from testing across 4 frontier LLMs and 10 benchmarks (~18,000 runs). The central finding is that no single paradigm dominates — ReAct outperforms alternatives on GAIA by 44 percentage points but underperforms on HumanEval by 15 points relative to CoT — and that paradigm routing before reasoning improves aggregate accuracy from 47.6% to 53.1%, recovering 37% of the gap between the best fixed-paradigm strategy (50.3%) and the oracle upper bound (55.4%). The router uses lightweight embedding-based selection trained offline on these runs to predict which paradigm will maximize accuracy for a given problem. Zero-shot self-routing — where the model itself chooses the paradigm — works reliably only for GPT-5, meaning that for most models explicit routing criteria are necessary.

Algorithm for the output document:
1. Restate the user's question, constraints, and evidence standard, then derive the subquestions or working items that paradigm routing needs to inspect.
2. Evaluate the problem against all six paradigms using routing criteria. Score each paradigm on: whether the problem requires multi-step reasoning (favors CoT, ReAct, Reflection over Direct), whether it requires external information or interaction (favors ReAct over pure reasoning paradigms), whether it benefits from explicit decomposition (favors Plan-Execute), whether the solution is verifiable (favors Reflection), and whether it involves computation or code (favors ReCode).
3. Select the best-fit paradigm with explicit justification naming the problem characteristics that drove the decision and why the chosen paradigm addresses them better than the runner-up.
4. Within the chosen paradigm, apply the paradigm's interaction pattern to reason through the problem. For CoT: produce stepwise reasoning. For ReAct: interleave reasoning with any tool-use. For Plan-Execute: decompose first, then execute. For Reflection: generate, critique, regenerate. For ReCode: write code, execute, observe output, revise. For Direct: produce the answer.
5. For each subquestion, case, option, hypothesis, or criterion the paradigm creates, write numbered public reasoning items that answer it before advancing.
6. Record assumptions, missing evidence, disconfirming signals, and confidence changes where they affect the analysis.
7. Synthesize the completed trace into the final answer, showing how the conclusion follows from the paradigm routing decision and the within-paradigm reasoning.

## Output Information
Write the scratchpad as Markdown in root memory/{question_name}.md before responding to the user. Include this scale note near the top of the file: "Scale: default - aim for around 100 numbered lines, or roughly 2,000 to 3,500 tokens, while adapting to the real complexity of the question." Use numbered scratchpad items for scanability, but treat the number target as approximate and subordinate to usefulness. Keep the scratchpad public, inspectable, and concise enough per line that the structure remains easy to review. After writing the file, respond with the path, the selected paradigm with justification, the scale note, and the final answer summary.

## Specify Files And Length And Structure Of Output
Write the artifact to memory/{question_name}.md at the repository root, using the literal memory directory name. Structure the file with the sections Question, Paradigm, Strategy, Scale, Paradigm Assessment, Scratchpad, Synthesis, and Final Answer. The Paradigm Assessment section should contain the evaluation of the problem against all six paradigms with the selected paradigm and justification. The Paradigm section names the chosen paradigm. The Strategy section should list the slash command. The Scratchpad section should target around 100 numbered lines or roughly 2,000 to 3,500 tokens of public scratchpad detail, adjusted reasonably for very small or unusually broad questions. Use subsections inside Scratchpad when the trace becomes long enough that phases, branches, hypotheses, cases, or criteria would improve readability. If the user supplies a domain format, evidence source, or output constraint, preserve it inside this structure while keeping the default scale approximate.
